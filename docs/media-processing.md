# 媒体分析、缩略图与推理管线

本页描述媒体处理的阶段、缓存、推理与异步提交约束。用户入口见[导入和整理媒体](./user-guide/media/import-organize.md)、[后台任务](./user-guide/workspace/workspace.md)和[分镜](./user-guide/storyboard/storyboards.md)。

## 登记、绑定与分析

媒体导入先登记项目条目，自动绑定在需要的数据到位后建立音频/字幕关系，后续分析补充封面及内嵌字幕。媒体分析队列在 `application/media/mediaAnalysisTask.ts`，不依赖导入页面是否挂载；每批等待前批以及指定的自动绑定前置任务，并在开始时检查当前项目 ID。

分析返回并不意味着可以无条件替换当前项目。`ProjectSystem/mediaAnalysisMerge.ts` 与相关命令以目标身份、素材指纹和当前数据为依据合并，保留用户在异步期间新增或修改的绑定、字幕和项目编辑。新增媒体与补分析是不同阶段，不能对已登记条目重复导入来补封面。

`find_media_needing_analysis` 扫描请求的已登记素材。仅文件确实存在时，对缺失内嵌文本字幕或视频封面缓存的素材返回 ID；位图字幕不作为可解析文本缺失条件。检查只取资产信息和是否缺失的标志，不复制潜在庞大的字幕条目集合。

媒体箱首次检查延迟约一秒，周期约一分钟；同一 ID/指纹维护重试间隔。它是自动修复机制，不是公开“重新分析”菜单。已经包含对应流和 cues 数据的轨道优先复用；缺数据而已有轨道时沿用原轨道 ID，补齐条目数和警告状态。无法读取源文件时，应先重新链接，代理不替代原始分析。

## 缩略图职责

| 阶段                  | 当前所有者                    | 主要约束                                                                             |
| --------------------- | ----------------------------- | ------------------------------------------------------------------------------------ |
| 媒体封面缓存读取      | `backend/thumbnail.rs`        | 只读取已有分析缓存；缺失返回无图，不隐式启动全视频分析                               |
| 封面生成              | 媒体分析任务                  | 共用分析队列和导入封面线程预算                                                       |
| 字幕/分镜多分辨率查找 | 后端缓存命令                  | 按素材指纹、取样位置及尺寸区分，校验载荷与版本                                       |
| 时间线请求与视口窗口  | `src/timelineThumbnail`       | 根据可见范围和分辨率需求调度、复用请求                                               |
| 实际取帧              | `extract_timeline_thumbnails` | 单次 FFmpeg 从同一帧分支输出多种尺寸，多尺寸以临时文件收集，控制工作线程和每图字节数 |
| 磁盘写缓存            | 后端 blocking 工作任务        | 不阻塞异步命令执行器，失败经类型化错误路径记录                                       |

后端可用缩略图宽度为 160、640、1280，对应 90、360、720 高；单请求最多三种分辨率。时间线 worker_count 默认四，限制为 1–8；FFmpeg 处理与输出线程预算再按输出数量分配，不能把请求数量直接当作无限子进程许可。单尺寸请求走直接输出 JPEG 的路径，不创建同样的多尺寸临时目录。

字幕缓存使用 100 ms 时间桶和 100 ms 邻近查找容差，分辨率间共用规范化取样位置。分镜缓存版本为 2，修正旧帧边界取样可能显示前一帧的问题；升级不应为了沿用旧图绕过版本检查。单张时间线 JPEG 上限为 8 MiB；缓存载荷、尺寸及图片校验失败按未命中或类型化错误处理。

临时目录在配置缓存根下的 `Timeline Thumbnail Temporary`，过旧临时目录以一小时阈值清理。处理结束尽力清理本次目录，清理返回值不影响已得到的取帧结果；不要把它描述成严格的删除保证。缓存文件不是源素材或项目备份，移动缓存不等于移动媒体，清理缓存也不应删除字幕标注和分镜。

## 分镜流水线与前端提交

前端 `useStoryboardDetection.tsx` 的共享 pending 集合以项目 ID 和视频/素材/指纹上下文去重，检测不依赖分镜面板持续挂载。来源新增只补缺失分镜；主动检测已有镜头/删除记录则询问合并、覆盖或取消。检测开始保存会影响结果提交的编辑签名，完成后若签名变化，再确认处理方式；对话框不继续占用已完成的任务槽。

合并调用 `mergeDetectedStoryboardShots`，将新切点加入当前有效镜头，不重复切点；覆盖重建 shots、deletedShots、shotStacks 和 shotAnnotations。结果提交前再次验证项目、媒体启用/在线状态与素材上下文，过期结果不可落到替换后的文件或另一项目。

后端每任务由 FFmpeg reader 提供 50 帧 RGB 块，最多四个块等待；统一推理线程轮转各队列，保持 100 帧输入、50 帧步长和边缘填充。会话空闲保温 30 秒，然后在锁保护下退役；失败与取消隔离在任务内。后端按物理核心数 C 限制提取并行度 W = min(C, 3)，每个提取的 FFmpeg 线程预算为 min(floor(C / W), 16)；进程级信号量保证直接后端请求也遵守此限制，子进程回收后才释放槽位。

Windows D3D11VA 是解码阶段的请求，不是无条件的硬件成功保证。驱动、FFmpeg 构建和源编码不兼容时提取会携带诊断失败；DirectML 会话创建或推理失败时按下述契约尝试 CPU。不要在文档中把这两类行为合并成同一个自动回退承诺。

## 统一调度和取消

任务立即进入 queued 状态，获得槽位后才执行媒体工作。最多三项分镜检测并行；其他操作独占，遵守先进先出。UI 非阻塞只说明仍可交互，不能据此并行执行全部代理、导出或绑定任务。

取消排队任务不启动 FFmpeg；取消运行任务请求底层停止，并由任务所有者在完成清理后释放槽。取消全部暂停补位，等待旧任务结束。取消不能回滚已经写出的文件或已经成功登记的媒体；提交者必须分别处理部分成功结果和当前项目身份。

导出在 `ExportSystem/exportTask.ts` 拍下来源与参数快照，共享同一任务系统。冲突确认也属于当前导出批次，取消会结束确认；成功才记录可复用设置。字幕、分镜和媒体箱来源共用临时导出范围编辑与撤销逻辑，不修改原始内容，也不触碰磁盘文件。

## ONNX 会话与回退

TransNetV2、字幕 Jina 和分镜 DINOv3 统一通过 `backend/onnx.rs` 的 `OnnxModel` 创建并调用。共享运行库由 `prepare:transnetv2` 准备；各模型资源见对应目录的 MODEL 或 README 文档。

会话创建优先探测 DirectML 适配器，失败后尝试 CPU。DirectML 会话顺序执行并禁用 memory patterns；CPU 使用可用逻辑线程数的一半，限制为 1–8 线程。推理阶段的 GPU 错误在 CPU 上重试同一输入，后续批次复用 CPU，不在提供器间循环。CPU 创建或重试也失败时保留两段诊断；缺失运行库、损坏模型与非法输入仍通过类型化错误报告。

互斥锁保证共享会话串行调用。回退保留模型路径、固定维度、批次与原始输入；仅在完整调用成功后发布结果。推理前、失败后、CPU 重建后和重试后均检查取消。任务最终报告实际使用的提供器。

## 分镜决策与选帧

`backend/storyboard/decision.rs` 只处理 TransNetV2 输出的逐帧概率：局部中位数和 MAD 估计背景，生成并合并候选事件，再提取事件特征、应用分类与可选校准，最后按成本阈值、非极大值抑制和最短镜头惩罚决定切点。

事件参数位于 `resources/transnetv2/storyboard-event-model.json`，特征顺序必须匹配。缺失配置使用相同默认参数，损坏配置明确报错。当前参数标记为 `bootstrap_uncalibrated`，不能宣称为经过训练或校准的生产模型。

`backend/storyboard_semantic/cses.rs` 使用 DINOv3 特征执行自适应选帧。`cache.rs`（Storyboard Keyframe）与 `index.rs`（Storyboard Semantic Search）共用 `storage.rs` 的记录、恢复和分卷层，分别存入首选项缓存根下的 `Storyboard Keyframe/<媒体指纹>/<方案与媒体版本哈希>/<顺序号>-<UUID>.bin` 和 `Storyboard Semantic Search/<媒体指纹>/<方案与媒体版本哈希>/<顺序号>-<UUID>.bin`。方案哈希包含模型/算法 recipe、媒体大小及修改时间；流与帧率在记录键中隔离。同一媒体的多个分镜聚合保存，单卷以 256 MiB 为上限，仅按大小分卷；顺序号直接从文件名解析，无须逐卷打开读取。媒体指纹复用导入时的 hash，不重新读取媒体计算 hash。记录身份包含模型/算法、媒体大小及修改时间、视频流、帧率和包含首尾的绝对帧区间，不包含路径、资产 ID 或面板 ID。旧存储格式不读取、不迁移。字幕语义索引仍使用 `Subtitle Semantic Search/<SHA-256>`；模型资源目录名不受影响。

分镜缓存是有版本的 bincode 数据，包含媒体/分镜身份、来源记录、全部初始探测与主动采集帧，以及每帧的绝对帧号、最终 vᵢ、完整 eᵢ、探测标记和选中标记。vᵢ 取主动采集后对扩展集合重算的最终值；eᵢ 保留 CSES 输入的 L2 归一化 DINOv3 CLS 向量，使用原有 float32 精度，不做量化或仅存帧间相似度。帧记录保留原始计算顺序，并保存初始/最终峰值和带宽、探测背景中位数/MAD、各项预算及公式常量。单帧分镜也执行编码并保存向量，vᵢ 为 0。这些数据可重演最终覆盖率选择，但缓存复用直接读取选中标记，不解码、不向量化、不重演算法。

媒体分卷使用带版本头的增量记录格式。记录头包含 magic、payload 长度、分镜键、payload SHA-256 和覆盖前述全部头字段的 SHA-256，随后是 bincode 数据与提交标记。先校验记录头再使用 key/length，按偏移读取后先校验 payload 再反序列化。Semantic 每条记录只包含一个分镜的部分或完整向量，读取仅解码请求的分镜；Keyframe 每条记录保存一个已完成分镜。头扫描与追加在进程内按媒体加锁，读取在锁内固定记录的文件句柄、释放锁后读取 payload，不占用全局分片锁。损坏中段可重同步到后续通过头校验且已提交的记录，有效末端推进到最后一条已恢复记录之后；追加只截掉其后的不完整尾部。

每批追加成功后检查一次回收条件：被覆盖或损坏记录的空间达到 `max(64 KiB, 有效记录字节数 / 2)` 时，流式复制各键最新且通过校验的记录到临时分卷。任何最新记录读取或校验失败都会中止压缩，仅记录后端日志并保留全部旧分卷，不向前台发出警告或影响已成功追加的返回结果；不会跳过失败记录再删除原文件。先同步所有替代文件，再改名发布更高顺序号的分卷并同步目录，最后删除旧分卷；复制可取消，发布阶段不可取消。中断时允许重复副本，后续恢复仍以较新记录为准。当前媒体版本的首批记录提交成功后，回收同一媒体指纹下的失效方案/媒体版本目录；同一进程内对已清理的版本不重复扫描父目录，不影响其他媒体。未再次写入的媒体不会主动扫描回收。该锁协议仅协调当前进程中的读写，缓存目录不支持多个应用进程同时写入。

Semantic 的一次 checkpoint 使用批量追加：一次加锁，写完多条独立提交的记录，每个涉及的分卷执行一次 `sync_all`，批末同步一次目录并运行一次维护；单条 Keyframe 写入复用相同接口。跨卷时先同步写满的分卷；取消或写入中断时同步已提交前缀、保留逐记录恢复粒度，当前未提交记录会截掉。Unix 还同步新建目录的父目录，以及压缩发布和删除所属目录；没有删除旧版本目录时不额外同步父目录。Windows 标准库没有目录 fsync 屏障，因此承诺文件内容同步及进程崩溃后的校验恢复，不承诺新文件、目录改名或删除在突然断电后持久化。缓存不是权威数据，未通过校验的记录会按需重建。

缓存按缺失范围补齐。完整分镜直接复用；缺失分镜单独补建；记录校验通过、仍可解析且模型/媒体身份匹配时，保留其中有效的帧向量，CSES 只为缺失或损坏的向量请求解码和推理，再重算该分镜的分数及选中标记。只有分数或选中标记无效时，可完全复用现有向量；不会因部分缓存缺失清空整个媒体。两套解码记录热缓存分别限制为 32 MiB，追加仅替换相应分镜的记录，不清空其他分镜；分卷偏移索引有界保留，以文件大小和修改时间检查外部变更。磁盘缓存不进入 `.lcp`。

选帧的贪心计算采用精确上界剪枝：覆盖率只增不减，主动采集权重中的覆盖缺口只减不增，所以历史边际增益可以作为下一轮的上界。仅当剩余上界严格小于当前最佳增益时停止检查；相等时仍执行原来的并列规则。此优化依赖非负权重和固定阶段内核，未来修改权重公式时必须重新确认单调性。新颖度仍按当前已编码帧的时间邻域计算，帧间余弦相似度跨阶段复用；采集已饱和时不构建候选时间矩阵。

DINOv3 和 SigLIP2 按正常任务的实测吞吐量在 2、4、8、16、32 帧间调整推理批量，帧数足够时从 8 开始。新会话首次真实推理也计入三次收敛计数；会话初始化、首轮预热、补齐的尾批次和解码等待不参与吞吐计时，仅使用有完整计时的形状比较平滑每帧耗时。每个编码器保留全部五种调优形状及必要的单帧恢复形状，不淘汰未采样挑战者；阶段切换和任务结束保留会话，复用输入张量及 RGB 归一化查找表，只请求 `pooler_output`。大批次失败先缩批重试原帧，缩到两帧仍失败才使用共享 CPU 回退；回退后清除 GPU 测速结果，后续形状直接创建 CPU 会话。

冷构建按媒体合并连续未缓存分镜，使用尽量少的 ffmpeg 进程连续解码到 256×256 RGB。探针推理边读取边缓存当前分镜的整段 RGB，主动采集复用该缓存，DINOv3 从同一批像素双线性降采样到 224×224；SigLIP2 直接复用选中帧的 256×256 像素。选帧后释放整段缓冲，仅选中帧通过有界媒体队列传给另一编码线程，使上一媒体的 SigLIP2 与下一媒体选帧、解码重叠。完整缓存不解码；只修复语义索引时仍只解码缺失的选中帧，合并邻近帧、跨越两秒以上的稀疏间隔时重新 seek。

Windows 解码请求 `-hwaccel d3d11va`，处理线程上限为 16。每个 FFmpeg 程序只查询一次 `scale_d3d11` 是否编译；可用时配合 `-hwaccel_output_format d3d11`，先在 GPU 缩到 256，再以 NV12 下载并转换为 RGB。首轮真实解码继续验证设备和媒体兼容性；失败时依次尝试显式 NV12 下载后软件缩放、原有自动下载、纯软件解码。已有稀疏 `select` 始终位于缩放和显式下载之前，减少不需要帧的下载与缩放。失败路径按程序、媒体路径和视频流有界保留，后续分镜跳过；仅在尚未输出任何像素且接收端仍有效时重试，部分流不重复播放到推理端。

解码器使用两帧传输块和至少 32 帧的队列，推理端按当前批量合并；切换批量不重启解码、不丢帧、不改变顺序。失败或取消时关闭接收端、终止解码并等待清理，再释放任务槽位。合并进程成功退出后才发布对应选帧缓存；语义索引仍须像素验证成功且向量完整才可检索。选帧占 75% 的进度，SigLIP2 向量化占 25%，按独立累计值加权相加，支持跨媒体重叠。

媒体元数据按素材解析一次，不重复计算文件 hash。当前文件大小和秒级修改时间须与导入资产一致，实际变化要求重新导入，避免在旧指纹下反复建库。缓存身份继续保留文件原始纳秒修改时间，不截成整秒，以保持现有目录哈希、记录键及持久化身份一致。

CSES 公式、计算顺序、帧预算、停止条件及并列决策规则保持不变。缓存 revision 保持原值：Keyframe 为 `dinov3-cses-v1`，Semantic recipe 后缀为 `rgb256-l2-v1`。256→224 的二次缩放与原来直接解码到 224 的像素不完全相同，新旧预处理不保证选帧逐帧相同；不同批形状或提供器的浮点计算也不承诺逐位相同。

资源准备会修正 DINOv3 的十二个注意力输出 Reshape，将 `allowzero=1` 改为 `0`。它们的目标形状均为 `[batch, tokens, -1]` 且前两维为正数，因此计算语义不变；此处理绕过 ONNX Runtime 1.24 DirectML 未推导 `-1` 而导致的形状检查失败。仅固定输入维度不能解决该问题。准备命令也会升级已下载的图，不修改或重新校验大体积权重文件；详见模型目录的 `MODEL.md`。

维护时检查去重键、取消释放点、配置写入顺序与项目身份；测试及文档规范见 [CONTRIBUTING.md](../CONTRIBUTING.md)。
