# 功能与操作覆盖清单

本清单回答两个问题：LineCut 当前有哪些用户可执行操作，以及每项操作在哪一篇专题页中得到说明。指南以源码中的菜单、按钮、输入框、复选框、下拉项、拖拽、滚轮、快捷键和对话框动作作为核对边界；实现细节和测试辅助接口不计为用户操作。

当前操作清单包含 **28 个功能组、339 项用户操作**。这些数字不是宣传口径，而是 `scripts/user-guide-operations.mjs` 中逐项登记的审计结果。每项都关联源码依据、专题页和文内说明文字，`npm run docs:check` 会在页面、章节、源码文件或说明依据缺失时失败。

> [!IMPORTANT]
> “覆盖”表示文档已经说明该操作的入口、前置条件、主要步骤、结果或限制，不表示所有功能都已实现。界面中禁用的预留命令也会被登记，并明确写成“当前不可用”，避免读者把它误认为可执行能力。

## 如何理解 333 项操作

计数单位是“用户意图明确、结果不同的动作”。例如“选择 H.264、HEVC、ProRes、VP9”属于同一个“选择导出格式”操作，其全部可选值在导出专题页中列出；“取消、跳过、使用唯一名称、覆盖”会产生四种不同冲突处理结果，因此分别登记。单纯展示的状态文字不计数，但只读、离线或任务繁忙导致的禁用条件要在相应操作中解释。

操作清单不会替代文章正文。清单用于证明范围，专题页负责说明：

1. 从哪里进入操作；
2. 选择什么对象、需要满足什么条件；
3. 鼠标、键盘、滚轮或拖拽的具体步骤；
4. 操作会修改项目、媒体引用、临时选择还是磁盘输出；
5. 什么情况下命令禁用，以及失败后如何核对；
6. 删除、覆盖、还原和重新切分等高风险操作如何恢复。

## 维护与验收

新增或修改用户可见功能时，应同时更新源码对应专题页、`scripts/user-guide-operations.mjs`、本清单的功能组统计，以及必要的截图说明。完成后至少运行：

```powershell
npm run docs:check
npm run docs:build
```

结构检查会验证每个 Markdown 页面、侧边栏路由、截图/TXT 占位关系，以及 339 项操作的页面、章节、源码依据和正文证据。VitePress 构建继续验证站内链接和最终可部署产物。无法从当前源码确认的行为必须明确写成“当前不支持”或“当前仅影响……”，不能把计划中的能力描述成已经可用。
