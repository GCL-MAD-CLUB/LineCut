# 故障排查

排错的目标是先缩小问题范围，再改变设置。请保留错误文字，从一个短小、可重复的样本开始，每次只改变一个条件；不要一开始就移动全部素材、清空所有缓存或覆盖原项目。

本页按依赖工具、媒体状态、导入导出和性能四类问题组织。每一节都从低风险、容易验证的检查开始。

## FFmpeg 与 ffprobe 问题

LineCut 使用 FFmpeg 执行媒体处理和导出，使用 ffprobe 读取媒体信息。路径配置不正确、可执行文件不可运行或硬件编码不可用时，导入分析、代理和导出都可能失败。

<GuideImage src="/images/troubleshooting/ffmpeg.png" alt="首选项中的 FFmpeg / ffprobe 设置" />

### 先检查首选项路径

1. 打开 [首选项](../projects/preferences)。
2. 检查 FFmpeg 与 ffprobe 路径是否都指向可执行文件，而不是其所在文件夹。
3. 如有疑问，使用各自的“浏览”按钮重新选择；不要手输一个未验证的路径。
4. 保存设置后重新尝试导入一个小文件或导出一个短片段。

应用提供“重置工具路径”操作，用于恢复工具路径设置；缓存目录和自动保存设置不会因这个操作而被重置。

### 常见症状

| 现象               | 可能原因                                   | 建议                                          |
| ------------------ | ------------------------------------------ | --------------------------------------------- |
| 导入后没有媒体信息 | ffprobe 不可用或源文件无法探测             | 重新选择 ffprobe；用另一份小样本验证          |
| 生成代理失败       | FFmpeg 路径、源媒体解码或输出目录问题      | 检查路径和磁盘空间；用常用 H.264 代理预设重试 |
| 导出失败           | FFmpeg 不可运行、编码组合或硬件加速问题    | 用 H.264/MP4、硬件加速或仅限软件试导出        |
| 硬件模式异常       | 驱动、显卡或 FFmpeg 可见的硬件编码器不兼容 | 更新驱动后重试；先选择“仅限软件”确认基础流程  |

### 收集排查信息

不要只写“导不出来”。请记录：应用版本、Windows 版本、FFmpeg/ffprobe 路径、源文件扩展名和编码信息、导出容器/分辨率/性能设置、完整错误文字，以及能复现问题的最小步骤。这样更容易判断是媒体文件、配置还是特定硬件的问题。

如果只有某一文件失败，优先怀疑该文件的编码或损坏，而不是立即重装应用。相关： [支持的格式](../reference/supported-formats)、[导出冲突与失败处理](/export/exporting)。

## 媒体离线、绑定和预览问题

媒体离线意味着项目保存的路径已经找不到原文件，常见原因是移动磁盘、重命名文件夹、改盘符或只复制了 `.lcp` 而未复制素材。离线项不会自动变成可用素材。

<GuideImage src="/images/troubleshooting/media.png" alt="素材箱中的离线媒体与重新链接入口" />

### 恢复离线媒体

1. 在素材箱定位离线项目；
2. 选择重新链接，并选择已移动的文件或包含它们的目录；
3. 核对名称和扩展名匹配结果，再确认；
4. 在源监视器中播放并检查字幕、音频和代理关系；
5. 立即保存项目。

批量移动项时，保持原始文件名和目录层级通常最省事。自动重新链接的可靠依据是当前的文件名匹配规则；对同名不同内容的素材，应逐一人工核验。

### 视频、音频和字幕不对应

一个项目可以包含多个视频、音频和字幕。若播放的声音或字幕不对，请使用 [绑定视频、音频和字幕](/media/tracks-binding) 检查绑定关系，而不是反复重新导入同一个文件。对于视频内的多个字幕流，请看 [内嵌轨道](/media/tracks-binding)。

### 预览卡顿或画面不对

- 检查当前是否在预览代理；代理文件可能与原始素材不同；
- 在较慢设备上生成代理，或降低代理尺寸；
- 关闭不必要的程序，确认磁盘和网络存储可用；
- 若仅某个文件无法播放，先查看它的编码信息和 FFmpeg 配置；
- 修改绑定、重新链接或代理后，重新定位一次播放头确认状态刷新。

不要在离线原始素材上依赖代理完成正式交付；正式导出前应确认原始媒体能访问，或明确选择了“使用代理”的审核工作流。

## 导入与导出失败排查

下面的清单按“最容易验证、最少改变项目”的顺序排列。每执行一步后，先在短样本上复测，避免在未知状态下反复改动大量设置。

<GuideImage src="/images/troubleshooting/import-export.png" alt="任务进度或错误通知" />

### 导入失败

1. 确认文件仍在磁盘上且自己能用其他播放器打开；
2. 确认扩展名属于当前 [支持的格式](../reference/supported-formats)；
3. 在首选项确认 ffprobe 与 FFmpeg 可用；
4. 用一个短、常见编码的 MP4 或 SRT 测试应用是否可正常导入；
5. 对单个异常文件，尝试用外部工具生成副本后再导入，并保留原文件。

### 导出失败

1. 确认导出来源至少勾选了一项，且每一项引用的媒体在线；
2. 改到一个本地、可写、空间充足的指定输出目录；
3. 选择“询问”或“新名称”来排除同名冲突；
4. 使用 H.264/MP4、匹配源、硬件加速做一个短试片；
5. 若失败，切换到“仅限软件”，再检查 FFmpeg 路径；
6. 记录错误信息后再调整编码、画质或代理选项。

### 成功但结果不符合预期

- 范围错误：检查勾选项、字幕入出点、分镜范围和合并模式；
- 没声音：检查来源音频绑定、音频开关和纯视频/纯音频容器；
- 文件质量差：检查分辨率、质量档和是否使用代理；
- 新文件找不到：检查输出目的地、子文件夹以及“导入项目”是否勾选；
- 打不开：换目标播放器或改用兼容性更广的 H.264/MP4。

### 提交问题前的最小复现

复制一个短的非敏感媒体，记下从新建项目到失败的每一步。附上截图、错误文本、应用版本和导出设置；不要上传含有保密内容的原始素材。

## 性能、缓存与稳定性

长视频、高分辨率素材、多轨音频、密集缩略图和自动分镜检测都会增加 CPU、GPU、内存、磁盘与媒体解码的负担。性能问题应先通过缩小工作集和验证代理来定位，而不是直接改变全部项目设置。

<GuideImage src="/images/troubleshooting/performance.png" alt="缓存与代理相关设置" />

### 预览不流畅

1. 确认源媒体未离线，且位于稳定的本地磁盘或可靠存储；
2. 为当前视频生成代理，先用较小尺寸验证效果；
3. 避免同时打开大量高分辨率媒体和后台导出；
4. 检查磁盘剩余空间，特别是缓存和代理所在磁盘；
5. 重启应用后只打开一个小项目，判断问题是否与特定项目有关。

代理有利于编辑流畅度，但正式输出要明确选择是否使用代理。详细做法见 [创建与管理代理](/media/offline-proxies)。

### 缓存策略

首选项中可以设置缓存目录。选择空间充足、读写稳定的本地位置；不要把缓存设为经常断开的移动盘或会被系统清理的临时位置。变更缓存位置前，请完成当前导出并保存项目。

自动保存快照也会使用缓存相关位置。降低自动保存间隔或提高快照上限会增加写入频率和磁盘占用；它们应在数据恢复需求与磁盘负担之间折中。

### 自动检测或导出耗时很长

这是媒体分析与转码的正常成本。先在短片段测试；确认范围无误后再处理长素材。导出时，较高质量、质量优先编码、较大分辨率和软件编码通常耗时更多。不要在任务运行时移动源素材或断开输出磁盘。

若应用持续无响应，保留任务状态和最后的错误信息，避免强制退出后立即覆盖自动保存恢复结果。重新打开后先确认项目和素材状态，再继续操作。
