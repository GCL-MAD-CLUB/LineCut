# 后端代码组织

`src/lib.rs` 负责应用启动、Tauri 命令注册和窗口生命周期。共享数据契约放在
`src/models/`，按媒体、工作区、导出、代理、探测、偏好设置和通知划分；序列化字段与默认值由对应模型维护。

| 模块                          | 职责                                         |
| ----------------------------- | -------------------------------------------- |
| `state.rs`                    | 应用运行状态、任务守卫与生命周期             |
| `tasks.rs`                    | 逻辑任务注册、取消、子进程登记和清理路径管理 |
| `ffmpeg/process.rs`           | 子进程创建、终止、输出读取与超时             |
| `ffmpeg/progress.rs`          | FFmpeg 进度协议、进度发布与停滞监控          |
| `ffmpeg/threading.rs`         | 解码和编码的线程预算                         |
| `cache.rs`                    | 通用缓存封装、编码与完整性校验               |
| `frame_trace/`                | 帧迹提取及其算法、数据传输和缓存策略         |
| `thumbnail.rs`                | 封面与时间线缩略图的生成和缓存策略           |
| `storyboard/`                 | 分镜检测、推理流水线与切分决策               |
| `media.rs`、`media_ingest.rs` | 媒体探测与导入分析                           |
| `export.rs`、`proxy.rs`       | 导出与代理业务流程                           |
| `storage.rs`、`workspace.rs`  | 配置、路径和工作区持久化                     |

## 帧迹处理

`frame_trace/command.rs` 协调来源查询、任务注册、缓存和解码。
`source.rs` 校验范围并取得媒体流信息；`decode.rs` 管理 FFmpeg RGB 解码；
`stream.rs` 逐帧读取并发送带边界差值的批次；`metrics.rs` 和 `ssim.rs`
计算颜色、锐度和动势；`types.rs` 定义传输数据及校验规则；`cache.rs`
负责帧迹专属的缓存身份、生成锁、原子发布和容量淘汰。

图像尺寸由 `frame_trace/mod.rs` 统一定义。修改缩放、颜色转换、定位策略或指标算法时，
需要同步更新帧迹缓存上下文，并检查浏览器算法的一致性。

## 依赖边界

- 数据契约不承担进程执行或任务生命周期管理。
- 业务模块使用 FFmpeg 基础设施和逻辑任务接口；不要把业务算法放入任务模块。
- 通用缓存不依赖缩略图或帧迹业务；缓存身份、锁和淘汰策略属于各业务模块。
- 指标算法与批次读取不访问应用状态，也不执行缓存目录扫描。
- 新增模块显式导入所需依赖；`backend/mod.rs` 保留已有业务模块的兼容出口。

本次整理保持 Tauri 命令名称、参数、序列化格式和缓存格式兼容。缓存上下文与版本未变，已有缓存可继续使用。
